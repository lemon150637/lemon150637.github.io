工作方法

AI 原生的产品交付流程

01

从用户场景出发写 PRD

先定义问题和边界：用户是谁、痛点是什么、P0/P1/P2 怎么划。文献阅读器项目直接产出了 1.9 万字 PRD。

02

AI 结对，我来架构与验收

Codex / Cursor / WorkBuddy / Claude 写代码，我做技术选型、安全边界设计（密钥不进前端）、结果验收。人机分工明确。

03

最快路径部署上线

CloudBase 静态托管、GitHub Pages、微信开发者工具真机验证——能上线就不停在 demo。

04

诚实度量，快速迭代

自检脚本回归、模拟器 + 真机双验证；每个 README 如实标注"已验证 / 待开发"的边界——对用户诚实，也是对产品诚实。

主线产品

「智慧识别」：一个需求的四代演进

普通人查法条这件事，我做了四代：从数据地基，到网站，到小程序，再到接入大模型。每一代解决上一代的真实短板。

v0

数据地基 · Python 流水线

裁判文书和法规都是非结构化长文本。先写流水线把"案例 × 法条"关联结构化，产出 Excel 数据表——检索产品先要有可检索的数据。

law-clause-pipeline →
v1

网站版 · 规则引擎，已部署

大白话输入 → 相关度排序 → 智能分析报告（风险提示 / 证据清单 / 诉讼时效检测）。108 条条文 + 25 个纠纷场景，纯静态零成本部署 CloudBase。

ai-law-search-web →
v1.x

小程序版 · 双端复用

用户在微信里，不在浏览器里。数据层、检索算法、分析规则三同源迁移，一次设计两端交付，7 个页面。
