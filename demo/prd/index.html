个人法学文献阅读与写作工作台 PRD

版本：v1.0（需求评审稿）
日期：2026-09-28
目标用户：以个人使用为主的法学研究者、学生与写作者
产品定位：将网页、PDF、Word 资料转化为可阅读、可回顾、可引用、可按主题导出的个人研究资料库。

1. 背景与产品目标

用户每天阅读大量资讯、论文、法律规范、案例和评论。资料分散在浏览器、下载目录和笔记软件中，阅读时形成的摘录与思考难以与出处长期关联，后续写作需要反复找原文，给大模型提供材料时还要再次整理。

本产品围绕一条完整流程设计：

收集资料 → 保留来源 → 阅读定位 → 摘录原文 → 记录思考 → 归入主题 → 回顾检索 → 写作引用 → 导出数据集。

第一版应让用户完成三个核心任务：

  1. 将一份网页、PDF 或 DOCX 导入后，能够再次打开并定位阅读。
  2. 在同一主题下汇集不同文献的原文摘录和个人思考，并能够追溯出处。
  3. 导出机器可读的 JSON，使每条资料保留内容类型、文献来源和原文位置，供后续问答或写作使用。

本 PRD 是目标需求，并不表示现有原型已经实现。现有基于 Koodo Reader 的原型已有项目克隆、笔记面板和 Markdown 导出代码；其首页与类型检查已验证，新增笔记完整交互仍待验证。网页采集、可靠定位、主题 JSON 导出和备份恢复均属于待开发范围。

2. 用户场景

场景 用户行为 预期结果
每日资讯收集 粘贴文章链接，或粘贴正文及来源信息 保存正文快照、标题、作者、发布与采集时间、原始链接
论文精读 拖入 PDF，选择一段文字并添加思考 原文摘录与个人思考分别保存，记录 PDF 页位置
Word 材料研读 导入 DOCX，按标题浏览并摘录 保留正文结构，摘录可定位至段落
专题研究 建立“平台责任”等主题，将资料和笔记归入 一篇文献或一条笔记可属于多个主题
写作准备 按主题检索、查看观点、返回出处 复制引文时一并获得出处和定位信息
数据集整理 选择主题和内容范围，导出 JSON 原文、个人思考、AI 内容可区分，记录可追溯
定期回顾 查看未读、阅读中、已读、待复习资料 可从上次位置继续阅读，或直接回到摘录位置

3. 产品原则与范围

  • 原始资料与加工结果分开保存。解析、清洗、OCR、AI 摘要不能覆盖原始文件或网页快照。
  • 原文摘录、个人思考和 AI 生成内容使用不同类型；界面与导出中均明确标识。
  • 缺少作者、日期、页码等信息时允许为空并提示补充，不能自动编造。
  • 本地存储优先。只有用户主动启用外部服务时，才向所选服务发送指定内容。
  • 导出 JSON 是可进一步用于检索增强问答的数据，不宣称可直接满足任意模型的微调格式。
  • 法律规范的有效性、案例权威性和观点正确性由用户核验；产品记录核验状态，不因导入而自动判定。

3.1 首版必需（P0）

网页 URL 导入及正文粘贴兜底、PDF 与 DOCX 导入、统一文献库、原始资料保存、来源编辑、阅读与进度、摘录定位、个人思考、主题管理、库内文本检索、引用信息复制、主题 JSON 导出、完整备份恢复。

3.2 后续增强（P1）

浏览器扩展采集、扫描件 OCR、旧版 DOC 转换、重复文献版本管理、批量元数据补全、引用格式模板、JSONL 与检索分块导出、主题回顾提醒。

3.3 暂不纳入首版（P2）

多用户协作、跨设备云同步、移动端、自动法律效力核验、应用内 AI 问答、自动生成文章、与 Word 写作软件深度联动。

4. 信息架构与主要页面

4.1 文献库

左侧：收件箱、全部文献、主题、待回顾、回收站。
主区域：文献列表和搜索筛选。
文献卡片展示：标题、作者或机构、资料类型、来源、日期、主题、阅读状态、摘录数、解析状态。

4.2 阅读工作台

左侧为目录或页缩略图，中间为原文，右侧为摘录、思考和来源信息。选择原文后提供“摘录”“摘录并思考”“复制含出处引文”。

每条笔记卡片始终展示内容类型、关联文献、原文位置、所属主题和修改时间。思考可独立创建，也可关联一条或多条摘录。

4.3 主题工作台

同屏查看主题说明、文献、摘录和个人思考。支持在主题内搜索、按时间和来源筛选、选择材料加入写作素材清单，以及导出预览。

4.4 导出与备份

主题导出用于内容交换；完整备份用于恢复应用。两者明确区分，不能让用户误以为只有文字的 JSON 可以恢复原始 PDF 或 Word 文件。

5. 功能需求与验收条件

F01 资料导入（P0）

输入方式：拖放文件、文件选择、批量文件、粘贴 URL、粘贴正文。

  • 网页：获取可访问正文，保留原始 URL、最终 URL、采集时间及正文快照。页面标题、作者和发布日期可自动提取，但需允许用户修正。
  • PDF：保留原始文件、提取文本并提供分页阅读。无法提取文本时仍可阅读，显示“扫描件或无可提取文本”，不产生空白的成功摘录。
  • DOCX：保留原文件，提取标题、段落、列表和基本表格。预览不承诺与 Word 完全同版式；复杂公式、批注、修订等提取限制应提示。
  • DOC：首版显示不支持并建议转换为 DOCX，不将其计入成功导入。
  • 无法采集的网页提供正文粘贴入口；保留用户输入的 URL，并标记采集方式为手动粘贴。不绕过登录或付费限制。
  • 每个任务显示排队、处理中、成功、部分成功或失败。失败可重试，单项失败不阻塞批次。
  • 使用文件内容哈希识别完全相同文件。URL 相同但内容不同的网页提示可能更新，不静默覆盖既有快照。相同标题不作为自动合并依据。

验收：混合导入 PDF、DOCX 和可访问网页后，成功项可阅读并具有稳定文献 ID；失败项说明原因；重试不产生无提示的重复记录。

F02 来源与文献元数据（P0）

通用字段：标题、作者或机构、来源类型、原始 URL、发布日期、采集日期、导入日期、语言、来源备注。

按资料类型增加可选字段：

  • 论文：期刊、年份、卷期、原文页码范围、DOI。
  • 法律规范：制定机关、文号、公布日、生效日、用户记录的效力状态、状态核验日期和依据。
  • 案例：法院、案号、裁判日期、案件类型、公开平台。
  • 网页资讯：网站名称、发布者、访问日期。

字段标记获取方式：自动提取、用户填写或外部补全；支持“待核验/已核验”。已核验表示用户确认，不表示平台认证。

验收：信息缺失不妨碍入库，但复制引用和导出时提示；未知值保持 null，不以导入时间冒充发布日期。

F03 阅读与原文定位（P0）

  • 保存每份文献的阅读位置、最后阅读时间及阅读状态。
  • PDF 使用从 1 开始的文件页序号，并可另存书内印刷页码；两者不可混淆。
  • DOCX 使用导入快照的标题路径和稳定段落标识，必要时记录表格位置；不生成未经验证的 Word 页码。
  • 网页定位到本地正文快照的段落，并保存选中文字的前后文。
  • 文本选择记录范围、原文片段和快照版本。跨段落摘录支持多个范围。
  • 点击摘录应回到绑定的快照并突出显示；无法可靠匹配时显示定位失效提示，不跳到猜测位置。

验收：重启应用后可继续阅读；PDF、DOCX、网页各至少验证一条摘录可以返回正确位置；网页线上内容变化不破坏已保存快照的定位。

F04 摘录与思考（P0）

  • 原文摘录保存原始选区文本及定位；可另存经过断行清理的文本，但不能替代原始摘录。
  • 默认不允许直接编辑“原文摘录”。需要改写时创建“个人思考”或“转述”记录。
  • 个人思考支持独立笔记以及关联多条摘录，支持主题、标签和修改时间。
  • 笔记自动保存，显示保存中、已保存或失败。离开有未保存内容的页面时提示；保存失败不清空编辑区。
  • AI 内容未来使用独立类型，保留生成时间及相关来源，不能自动归类为原文。

验收：原文与思考在界面和导出中不会混为同一字段；模拟保存失败后内容仍可复制或重试。

F05 主题与回顾（P0）

  • 支持创建、重命名和归档主题；首版使用扁平主题，标签用于进一步分类。
  • 文献与笔记分别建立多对多主题关系。将文献加入主题不自动意味着其全部笔记均与该主题有关。
  • 支持主题内按资料类型、阅读状态、标签、日期及有无思考筛选。
  • 支持手动加入待回顾、标记回顾完成，记录最近回顾时间；自动提醒放入 P1。

验收：一条摘录加入两个主题只保存一份内容；修改主题名称不改变主题 ID；归档主题不删除文献和笔记。

F06 检索与写作引用（P0）

  • 检索范围包括标题、作者、正文、摘录、个人思考和案号等元数据。扫描件未 OCR 的部分明确不进入全文检索。
  • 结果展示命中片段、内容类型、文献出处和位置；可打开原文或笔记。
  • “复制含出处引文”输出选定摘录及标题、作者、来源、日期、页码/段落等现有信息。
  • 首版提供清晰的通用出处文本，不宣称完全符合某一期刊或引用标准；规范化样式作为 P1。
  • 写作素材清单引用原有记录 ID，不复制出与来源脱离的笔记副本。

验收：通过摘录关键词能检索到对应记录；复制结果不遗漏来源和定位；缺失出处有提示且不被自动填造。

F07 按主题导出 JSON（P0）

导出步骤：选择主题 → 确认范围 → 选择内容类型 → 检查缺失来源及敏感标记 → 预览 → 导出。

  • 支持多主题并集；同一记录命中多个主题时只输出一次，保留全部主题 ID。
  • 默认导出直接关联所选主题的摘录与思考，并附上这些记录引用的文献、快照定位信息。
  • 可显式勾选“包含主题文献的所有笔记”“包含未摘录文献的元数据”“包含文献全文”。全文默认关闭。
  • 原文、个人思考、转述、AI 内容分别可选；AI 内容默认关闭。
  • 若选中思考引用了被过滤的摘录，预览说明该依赖，允许补入关联摘录或仅保留明确的外部引用，不产生无法解释的悬空 ID。
  • 导出前显示文献数、记录数、原文/思考数量、缺失来源数、定位异常数和全文包含情况。
  • 导出包写入 schema_version、导出时间、应用版本、范围和过滤条件；采用 UTF-8。
  • JSON 不嵌入二进制文件，不导出本机绝对路径。每个文件/快照可通过稳定 ID 与内容哈希识别。
  • 缺少来源可由用户选择排除或带警告导出，不能假装完整。

验收：文件可被标准 JSON 解析器读取；通过固定版本 JSON Schema 校验；记录 ID 唯一；包内引用可解析或明确标注为外部引用；数量与预览一致。

F08 备份、恢复和删除（P0）

  • 完整备份包含原始文件、正文快照、数据库、笔记、主题与版本清单。
  • 恢复先校验版本及完整性，预览冲突，再执行；失败保留原有数据。
  • 文献删除先进入回收站，关联笔记与定位随之保留并可恢复。
  • 永久删除前展示影响范围并确认；不得留下无提示的孤立笔记。
  • 网页缓存存储有容量风险，提示使用持久目录或桌面数据目录，提供容量与备份状态。

验收：在独立测试数据目录恢复备份后，原始文件可打开，主题关系完整，摘录与思考内容相同，定位可用。

6. 数据模型与 JSON 契约

核心实体：Document（文献）、Snapshot（不可变内容快照）、Annotation（摘录/思考）、Topic（主题）、ReadingState（阅读状态）、WritingCollection（写作素材清单）。

所有实体使用稳定 UUID。文件名、标题和数组顺序均不能作为关联主键。时间采用 ISO 8601；仅知道日期时保留日期，不补造时分秒。所有缺失信息使用 null 或按 Schema 约定省略。

7. 非功能要求

以下为待用固定测试机验证的目标，不是已实现的承诺：

  • 容量基线：10,000 份文献、100,000 条笔记；先明确测试机与平均文本规模。
  • 本地检索 P95 响应目标不超过 2 秒；长任务后台执行并显示进度。
  • 普通笔记编辑停止后 1 秒内触发保存；保存成功后才能展示“已保存”。
  • 网页和 DOCX 解析后的 HTML 必须净化，禁用脚本和危险 URL；不执行文献内宏或主动内容。
  • 文件扩展名与实际格式交叉检查；损坏或加密文件提供明确错误。
  • 默认外部请求应可说明用途；不得将全文、笔记或用户数据悄悄发送给 AI 服务。
  • 数据升级需有版本迁移及失败恢复方案；备份需校验文件缺失和哈希。
  • 基本交互支持键盘、可读状态提示及清晰的原文/个人观点标签。

8. 验收与成功指标

首版发布必须完成一条真实端到端流程：网页、PDF、DOCX 各导入一份 → 各创建摘录和思考 → 归入同一主题 → 关闭并重启 → 返回原文位置 → 复制含出处引文 → 导出 JSON → Schema 与引用完整性校验 → 完整备份恢复。

另外覆盖：重复导入、网页失效、扫描 PDF、中文乱码、缺失作者、同名文件、跨段落摘录、笔记保存失败、多主题去重、主题归档、回收站恢复及恢复冲突。

产品成效通过用户试用观察，不依赖默认上传行为数据：

  • 能否在 30 秒内从一条写作素材返回出处。
  • 摘录是否全部保留来源关联和类型标记。
  • 一次主题导出是否无需手工修复即可解析与检索。
  • 重启与备份恢复是否发生内容或关联丢失。
  • 用户每周从已有文献中实际复用多少条写作素材。

9. 实施阶段

阶段 A：可靠入库与阅读

确认本地数据目录和统一数据模型；接入网页、PDF、DOCX；完成导入状态、来源编辑、快照和阅读定位。验收三类资料各一条完整阅读流程。

阶段 B：研究笔记与写作素材

完成原文摘录、思考、多主题关系、搜索、回顾和含出处引用。迁移现有原型的独立笔记存储，避免继续形成多个不能统一备份的数据来源。

阶段 C：数据集与可靠交付

发布 JSON Schema 和导出校验；完成范围预览、依赖处理、完整备份恢复及端到端测试。提供稳定的本地启动方式与数据位置说明。

阶段 D：增强能力

根据实际瓶颈再加入 OCR、浏览器扩展、引用样式、分块 JSONL、应用内 AI 问答和桌面安装包。

工期需在检查现有项目解析、定位和数据库扩展能力后估算，本 PRD 不预设完成日期。

10. 待确认决策与默认方案

决策 默认方案 影响
使用设备 单人 Windows 本地使用 暂不增加账号系统和云同步
Word 范围 首版 DOCX，DOC 后续转换 控制格式兼容成本
扫描材料占比 首版提示需 OCR，P1 接入 如扫描资料占多数，OCR 应提升为 P0
网页采集 URL 导入 + 手动粘贴兜底 扩展留待高频采集验证后实现
